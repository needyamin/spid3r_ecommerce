The framework is functionally broad (router, ORM, SpiderBD views, queue, cache, auth/JWT, mail, WebSocket, 3 DB drivers) and has good security fundamentals (CRLF-safe headers, signed cookies, constant-time compares, path-traversal guards, SQL identifier checks). What makes it feel "not a perfect framework" is: (a) code still written in the pre-1.1 verbose style, (b) a few real correctness bugs, (c) config that fights the runtime (ini keys, hard-coded debug), (d) repo/folder hygiene, and (e) missing production tooling (no lint/format gate, no storage:link, unpinned installs).

3. Real bugs found (verified in source)

P0 B1 — Multiple cookies are comma-joined into one Set-Cookie

framework/Response.matrix L115-121 and framework/Session/Session.matrix L134-135 merge cookies with ", ". RFC 6265 forbids this; browsers parse it as one cookie, so the 2nd cookie (e.g. session + CSRF/flash) is lost or corrupted. The comment "safe here — never Expires" is not true for SameSite=…, Secure parsing by every client/proxy.

Fix: stdlib http already emits "each entry in a cookies map as its own Set-Cookie header" (STANDARD_LIBRARY §WebApp extras). Store self.cookies = [] on Response and pass them through that mechanism at finalize_http_response. Add a test asserting two cookies → two headers.

P0 B2 — Queue never reclaims a stale reserved job

Queue.pop() selects reserved_at = 0 OR reserved_at < cutoff (retry_after), but then claims it with .where("reserved_at", 0).update(...) (Queue.matrix ≈ L176-188). For an expired reservation reserved_at != 0, so the update affects 0 rows and the method returns null — the crashed job is stuck forever while retry_after in config is dead.

Fix: make the claim conditional on the value just read: .where("reserved_at", job["reserved_at"]) (compare-and-swap). Add a test: reserve, advance time/set reserved_at old, pop again → job returned with attempts == 2.

P1 B3 — Hard-coded examples/spid3r_web/ paths in the shipped app

Application.try_serve_static looks in examples/spid3r_web/public/; tests/run_all.matrix sets SPID3R_PATH to examples/spid3r_web. This is a leftover from when the framework lived inside the language repo. It makes the lookup order surprising and adds a second place static files can be served from.

Fix: a single configurable paths.public (default public); delete the fallbacks.

P1 B4 — tests/run_all.matrix fails when run directly

spid3r run tests/run_all.matrix → module 'framework/Console/TestRunner' not found. It only works via spid3r magic test because SPID3R_PATH is set externally. Any of the 17 test files has the same problem when run alone (spid3r check without SPID3R_PATH reports an error for every framework file).

Fix: declare the module path once (spider.toml / spid3r.ini modules.path = ., doc'd as SPID3R_PATH alias) and commit a project-level spid3r.ini; or make imports relative.

P1 B5 — is_unsafe_path over-blocks; static files are fully read into memory

Any URL containing .. or : is rejected, so legitimate names like app..min.js or v1:2.css 404. Every static response uses read_file (whole file in RAM, no Range, no gzip). Fix: split path into segments and reject only a segment equal to ..; stream large files (the runtime has tcp_send_file / stream_source already used by SSE); add .mp4/.webm/.mp3/.wasm/.zip MIME types via a constant map.

P2 B6 — Cache file store is not atomic

CacheStore uses plain write_file (L255). A crash or concurrent worker can leave a half-written JSON. The runtime exposes write_file_atomic (SECURITY.md covered natives). Fix: switch to it for cache, .env writes (key:generate), and the migrations registry.

9b. Migration registry.matrix — why it exists and how to make it Laravel-like

You are right: Laravel has no such file. php artisan migrate scans database/migrations/*.php at runtime and requires each file. Spid3r import statements are resolved before the program runs (compile-time), and I found no runtime import / eval in docs/. So the framework generates database/migrations/registry.matrix (imports + kernel.register_migration(new X()) lines) via ConsoleKernel.sync_migration_registry (ConsoleKernel.matrix ≈ L522-596), auto-run by migrate and make:migration. It works, but it is a generated file living inside the user's folder.

fn content_type_for(path: string) -> string {
    let ext = path.split(".").pop();
    return MIME.get(ext) ?? "application/octet-stream";
}
